# QA Report: Tessera Milestone 2 exit

**Date:** 2026-10-11
**Phase:** 5 Verification, Milestone 2 exit. Repeats the M1 interim pass (`2026-10-11-qa-report.md`) with the M2 features added: typed and choice cards, the Markdown deck format, syntax highlighting and diagrams, the Claude skill, the API token, the host check, Firefox and WebKit, the release pipeline, and the image scan.
**Feature slug:** `tessera-v1`
**Commit verified:** `1884089` on `main` (CI green on `ad454a0`, the last code commit), plus the uncommitted test additions listed under "Gaps found by the mutation check".
**Environment:** Windows 11, Node 24.15.0, Chrome and Playwright WebKit locally, production build. CI on GitHub (Ubuntu) for Chromium, Firefox, WebKit, and the container jobs. No Docker on the development machine.

## Verdict

**The M2 slice is sound and ready for the owner's own try-out. It is ready for a `v0.1.0` tag once the owner-only items below are done.** No blocking defects. The first CI run after M2-15 failed three times (two test races, one real image finding); all three are fixed and the run on `ad454a0` passed every job. Four deliberate-bug checks survived the first mutation round; three were real test gaps and are now closed, one is harmless.

Not exercised, and so not claimed: the compose wrappers on a real host, a disk-full volume, a multi-day soak, any screen reader, a real Safari or iPhone, and the skill in a real Claude conversation. These are listed again at the end with who can close them.

## Do the tests catch real bugs? (mutation check on the M2 code)

Twenty-six deliberate bugs were introduced one at a time into the M2 logic (typed matcher, API token and web page detection, host check, choice shuffle and grading, format detection, Markdown parser errors), and the whole unit and integration suite was run each time.

**First round: 22 caught, 4 survived.**

| Survivor | Verdict | Action |
|---|---|---|
| A trailing hyphen counted as sentence punctuation in a typed answer (`word-` matched `word`) | **Real gap.** The tests covered a hyphen inside an answer, not at its end. | Test added: `-`, `/`, `)`, `_`, `*` at the end are kept. |
| `.localhost` names no longer treated as loopback when `TESSERA_ALLOWED_HOSTS` is set | **Real gap** in a rarely used path. | Test added. |
| A deck starting with `---` but with no `tessera:` line was not read as Markdown | **Real gap.** Another rule masked it for normal decks. | Test added, including the code-fence wrapper. |
| Every code fence line skipped at the start of a pasted deck instead of only the first | **Harmless in practice.** A second fence line does not change the answer for any input a person pastes (the later rules reach the same result). Left as is. | None |

**Second round on the three gaps: 3 of 3 caught.** Final: 25 of 26 caught, 1 judged equivalent.

Also caught by the existing tests, worth naming: an ignored accept list, a case-folding or NFKC removal, empty input matching, right answer suggesting Again, same-site treated as the web page, `/api/decks` open without a token, undecoded paths slipping past the token (`/%61pi/decks`), length-only token comparison, an Origin with a path accepted, a missing marker header, a substring wildcard host match, every dotted name allowed, a shuffle that never moves the last item, grading by position, an order that never changes between showings, and the Markdown parser's two newest errors.

## Observations

- **Request logging volume.** The server writes one log line per request. Under the soak load (about 225 requests a second) that is 53,000 lines in four minutes. Real use is a few hundred requests a day, so this is not a problem, but `compose.yaml` sets no log rotation and Docker's default driver never trims. See security review S-11 for the suggested setting.
- **Memory.** About 315 MB resident under load, 256 MB idle after start, on Windows with Node 24. Comfortable for a homelab, but not tiny.
