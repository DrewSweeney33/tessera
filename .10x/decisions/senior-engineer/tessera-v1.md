# Senior Engineer Decisions: tessera-v1

**Date:** 2026-10-10
**Phase:** 3 Planning
**Companion:** `.10x/decisions/engineering-manager/tessera-v1.md` (task list and sizes)

This file gives the implementation approach per task: files to touch, the test to write first, and what to watch. M1 and M2 are specified fully. M3 to M5 have approach notes only and are re-planned at each milestone start.

## 1. General approach

- **Test first for pure code.** `core` and the planning and queue logic are written test-first. UI is written, then covered by Playwright.
- **One task, one commit group.** Run `npm run verify` before each commit. Conventional Commit messages with the co-author line.
- **Fixtures are assets.** Every bug and every ADR rule adds a fixture. Fixtures live in `tests/fixtures/` and are shared by unit, integration, and e2e tests.
- **Review checklist per task** (self-review before commit): layer rules respected, no `Date.now()` or `Math.random()` in logic, no SQL outside repos, no `{@html}` outside `Markdown.svelte`, errors returned as `Result` for expected failures, no card content in logs, docs updated if user-visible.

## 4. Approach notes for later milestones

**M3**

- Leeches: flag inside `submitReview` after the update (same transaction). Report builder is a pure formatter fed by repo queries so it is testable with fixtures. Cap at 30 leeches and 10 tags, and state the cap in the report. Wrong typed answers are stored in `review_log.typed_answer` already (M1 schema).
- Export must emit ids and round-trip through import with no diff.
- Backup streams a temp file then deletes it. Test that a restored file opens and passes an integrity check.
- Settings UI writes through a validated settings repo. Changing retention applies from the next review, no mass rescheduling in v1.

**M4**

- Cram selection pure with injected rng. The invariance test snapshots `card_state` rows before and after a simulated session and compares.
- True retention counts only `mode = 'review'` rows whose pre-review state was Review. Forecast uses `due` dates grouped by study day.
- Charts as small Svelte SVG components with text alternatives (a table view for screen readers).

**M5**

- PWA: manifest, icons, a service worker that caches only the static shell and never API responses.
- Accessibility: axe checks in Playwright for each screen, keyboard-only run, 200 percent zoom, contrast tokens verified.
- Final QA and security passes follow the checklists in the QA and Security roles, with reports in `.10x/reviews/`.

## 5. Cross-task technical decisions

| Topic | Decision |
|---|---|
| Fuzz in tests | Off. A separate distribution test checks fuzz stays within bounds. |
| Test database | Temp file per test, never `:memory:` for integration tests, because WAL and backup behavior differ. |
| Browser tests for sanitization | Real browser, not jsdom. |
| Prefetching the next card | Not in M1. Add in M5 only if grade latency is measurable behind a proxy. |
| Undo last grade | Not in v1. Note as a candidate for v1.1 since keyboard misgrades are likely. |
| IDs in URLs | Deck ids are slugs, card pks are never exposed in URLs, use keys. |
| Dev data | `npm run dev:seed` loads the example decks into a dev database. |
