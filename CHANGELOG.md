# Changelog

All notable changes to Tessera are written here. The format follows [Keep a Changelog](https://keepachangelog.com), and versions follow [Semantic Versioning](https://semver.org).

## [Unreleased]

### Changed

- **A new look, for a phone and a computer.** Every screen was redesigned. On a phone, the navigation is a tab bar under your thumb (Decks, Import, Leeches, Settings, with a count on Leeches), and Trash and Backups are one tap away at the bottom of Settings. On a computer it is a rail down the left side. The deck list now opens with a Today card that shows how much is waiting and starts a session in one tap, followed by a tile for each deck with its new, learning, and review counts. The study screen keeps the card in the middle with a progress bar above it and the next action docked at the bottom, so a thumb can reach Show answer and the four grade buttons. Nothing about how studying, importing, or editing works has changed. The look keeps Tessera's warm paper and verdigris colours, in light and dark, and every screen is checked for contrast and keyboard use as before. The notes are in `docs/design.md`.

### Added

- **Folders for your decks.** On the decks screen, **New folder** makes a folder (a course, a project), and **Move decks** lets you tick decks and move them into a folder, between folders, or back out. Decks are shown grouped by folder, with the decks that are in no folder under **Ungrouped decks**, so nothing is hidden. A folder can be renamed, collapsed (a folder with many decks starts collapsed, and the choice is remembered), and deleted: deleting only puts its decks back in the ungrouped list, and no deck, card, or review is deleted. A deck is in one folder at most and folders do not nest. **Study folder** starts a session with only that folder's decks, in deck title order (`/study?folder=3`, and `?folderId=` on `GET /api/study/next`, a `folderId` on `POST /api/study/review`). **Stats** on a folder shows what studying its decks has added up to: reviews today, over 7 days and over 30 days, time spent, how much you recalled (reviews of learned cards graded Hard, Good, or Easy), the streak of study days, the last 14 days as a chart, cards by stage, open leeches, and the weakest tags. Folders live in Tessera's own data, not in the deck file, so importing and exporting decks is unchanged and a re-imported deck stays in its folder. Also `GET` and `POST /api/folders`, `PUT` and `DELETE /api/folders/:id`, `GET /api/folders/:id/stats`, and `PUT /api/folder-assignments`; `GET /api/decks` now also answers with `folders` and each deck's `folderId`. This adds one table (`folders`) and one column (`decks.folder_id`) to the database, so the first start after upgrading makes the usual backup copy before the database is upgraded. Backups and restore include folders, and a backup made before this version restores and is upgraded when it is opened.
- **Bulk import.** On the Import page, choose or drop several deck files at once (JSON and Markdown can be mixed). Each file becomes its own line with its own status, **Preview all** checks every file, and **Import** adds the ones that are ready, so a file with a mistake never holds back the others. Two files in one batch with the same deck id are caught before anything is imported, and files that are not decks are skipped with a message. One file still goes into the paste box as before. No server or API change: each file is one `POST /api/import`.
- **New deck** in the web page: make an empty deck by hand from a title, with an optional description, tags, and id. The id is made from the title and shown while you type (a second deck with the same title gets a number), and a taken or invalid id is explained next to the field. A deck with no cards says so on the home page. Add cards to it by importing a file with its deck id. Also `POST /api/decks`. A deck with no cards answers an export request with a clear message instead of an error.
- A deck can be exported: `GET /api/decks/:id/export` sends the deck as a JSON download, or as Markdown with `?format=md`. The file has every card with its id, type, text, tags, and order, so importing it again changes nothing and creates nothing. Cards you removed and decks in the Trash are not in it, and a Markdown export of content that format cannot hold says which card and points to JSON.
- **Edit a deck in the web page.** Press Edit on a deck to change its title, description, and tags, edit any card with a live preview of how it will look when studied, add cards of all four types, and remove cards. The page checks cards as you go and says what is wrong beside the field. Review changes shows the same preview as an import, then Save changes applies it through the import code, so a card you edit keeps its id and its history. A removed card is archived (kept with its history) and can be put back until you save. A card keeps its type, because changing type would erase its history. Export JSON and Markdown are buttons in the editor.
- `GET /api/decks/:id` returns a deck as a document with a `revision`, and `POST /api/import` accepts `expected_revision`: a save made from an out-of-date copy is refused with HTTP 409 instead of overwriting newer changes. Studying does not change the revision, only changes to the deck do.
- **The Trash.** Press Move to Trash in a deck's editor and the deck leaves your list and your study sessions, keeping its cards and everything you studied. Open Trash from the deck list to restore it, or to delete it for good: that needs the deck's title typed, says how many cards and reviews go with it, and saves a copy of your database first (`pre-delete-<deck>-<time>.db` in the backups folder). If the copy cannot be saved, nothing is deleted. Also `GET /api/trash`, `POST /api/decks/:id/trash`, `POST /api/decks/:id/restore`, and `POST /api/decks/:id/delete-forever`.
- **Start a deck over.** Press Start over in a deck's editor and every card goes back to new, so you can study the whole deck again from scratch. Your review history is kept and the reset is recorded. It needs the deck's title typed and saves a copy of your database first (`pre-reset-<deck>-<time>.db` in the backups folder). Also `POST /api/decks/:id/start-over`. This adds one table to the database (`deck_resets`), so the first start after upgrading makes the usual backup copy before the database is upgraded.
- **A Backups page.** Back up now, see every backup with why it was taken, download one to keep on another disk, and delete the ones you do not need. Also `GET /api/backups`, `POST /api/backups`, `GET /api/backups/:name` (a download), and `DELETE /api/backups/:name`. A backup is named by its file name and never by a path: only a plain file in the backups folder that the list shows can be downloaded or deleted, and never the live database. Restoring is still done from the host, as the operations guide describes.
- **Restore from the Backups page.** Press Restore on a backup to see what it holds beside what Tessera holds now, type `restore`, and Tessera saves a copy of the current data, stops, and is started again by its restart policy. At that start, before the database is opened, the backup is put in place and the data from before is kept as `tessera.db.before-restore-<time>`. A crash at any step leaves the old data or the whole backup, never a mix, and the next start finishes the job. A file that is not a Tessera database, is damaged, or comes from a newer version is refused with the reason. Needs the restart policy in `compose.yaml` (the operations guide says what to do without one). Also `GET /api/backups/:name/preview` and `POST /api/backups/:name/restore`.
- **Leeches and the weak-spot report.** The deck list links to a Leeches page: the cards you keep forgetting (flagged after eight lapses), each with the deck, the lapse count, and the wrong answers you typed. Reset a card you have fixed, or set it aside until you put it back. Below them, your weakest tags from your reviews of learned cards over the last 90 days. **Copy the weak-spot report for Claude** puts your worst cards on the clipboard as ready-to-edit deck blocks in the import format, with a request to rewrite them and keep every id and type. Claude's answer imports as usual and updates just those cards, keeping their history. At most 40 cards and about 60,000 characters, worst first, never cutting a card. Also `GET /api/leeches`, `GET /api/report/weak-spots` (Markdown or JSON), `POST /api/leeches/:cardPk/:ordinal/reset`, and `POST /api/cards/:cardPk/suspend` and `/unsuspend`. The Claude skill now explains the loop. `GET /api/decks` also answers with `openLeeches`.
- **A Settings page.** Change new cards per day (for each deck), reviews per day, target retention, the hour the study day starts, the leech threshold, and whether new and due cards are mixed. Each setting says what it does and what changing it affects, and a change that has a bad value is refused as a whole with every problem named beside its field. The time zone the study day uses is shown (it is set by `TZ` where Tessera runs). Also `GET /api/settings` and `PUT /api/settings`.
- **Mixing new and due cards now really mixes them.** The option used to shuffle within the due cards and within the new cards, with the due cards always first. With it on, a due card or a new card is drawn at random in proportion to how many of each are waiting (three due and two new: three in five are due), and then a random card of that kind. Cards you are in the middle of learning still come first, and other blanks of a cloze card you just answered stay buried.

## [0.1.1] - 2026-10-12

Fixes found by running 0.1.0 on a real homelab Docker host, and a tool for testing the real image on your own host.

### Added

- A live-image test harness (`npm run live:test`, guide in `docs/testing-on-your-host.md`) that runs the real image as a throwaway test instance on your own Docker host over SSH and checks it: container hardening, the smoke, security, and speed tests over the network, backup and restore with the operations guide's own commands, a crash, a hard kill and a graceful stop, a full disk, and an optional soak. It never touches the instance you use.
- The deployment guide shows how to run the published image with no source or build, as a hardened compose file with a pinned version. A test keeps the example as locked down as the repository's own `compose.yaml`.

### Changed

- The container's logs are now rotated (three files of 10 MB) in the sample `compose.yaml`. Tessera logs one line per request, and Docker keeps logs forever by default. If you wrote your own compose file, add a `logging` section (see the operations guide).

### Fixed

- When the disk that holds the Tessera data is full, an import or a grade now says so (HTTP 507, with what to do) instead of "Something went wrong on the server". A read-only or unreachable data folder gets a plain message too (HTTP 503). Nothing was ever damaged: the integrity check passes after a full disk, and the next try works once there is space. Found by testing the real image on the homelab.
- The browser tab showed the Svelte logo from the project starter. It now shows Tessera's own mark, readable on light and dark tab strips.
- The manual backup command in the operations guide failed on a fresh install, because the `/data/backups` folder only appeared after the first database upgrade. Tessera now creates the folder when it starts. If you are on 0.1.0, run `docker compose exec tessera mkdir -p /data/backups` once.

## [0.1.0] - 2026-10-11

The first public version: import decks from Claude in JSON or Markdown, study with spaced repetition, and run it yourself in a container.

### Added

- Import a deck by pasting JSON from Claude, choosing a file, or dropping one. A preview shows exactly what will change before anything is saved: the old and new text of each edited card, a warning when a card changes type (which erases its progress), a warning when new cards look like old cards under new ids, and the cards the file does not mention. Errors name the field and give line and column for syntax mistakes, and "Copy errors for Claude" produces a message that gets the deck fixed in one round trip.
- Decks can also be written in Markdown: a block of deck details at the top, then `## card-id` headings with `Q:`, `A:`, `Cloze:`, `Answer:`, and `Choices:` lines. The import page and the `/api/import` endpoint (`Content-Type: text/markdown`) take either format, the page works out which one you pasted, and the same deck gives the same import in both. Errors in a Markdown deck give the line number.
- Re-importing a revised deck keeps your progress. Cards are matched by `id`. Importing an unchanged file changes nothing.
- Study with FSRS spaced repetition. Keyboard first: Space shows the answer, 1 to 4 grade it, H shows a hint. Interval labels on the buttons, daily new and review limits, cloze blanks scheduled separately and buried for the day.
- Four card types in the deck format: basic, cloze, typed answer, and multiple choice. Typed cards have an answer box and compare what you type with the answer and the accepted alternatives, ignoring case, extra spaces, and a final full stop. Choice cards show their options in a shuffled order (the same order if you refresh) with keys 1 to 9. Both suggest Good or Again and mark the right answer, and you can always pick a different grade.
- Code in cards is highlighted for 23 common languages (Python, PowerShell, Bash, SQL, YAML, JSON, TypeScript and more), readable in both themes. A `mermaid` code block is drawn as a diagram (flowcharts, sequence, state, class, entity relationship, pie, Gantt, and mind map diagrams were checked), with its source underneath. If a diagram cannot be drawn, its source is shown with a note. Both load only when a card needs them, and neither needed a change to the Content Security Policy.
- A Claude skill (`claude-skill/tessera-deck`), a deck format reference (`docs/deck-format.md`), a guide to making decks with Claude (`docs/claude-workflow.md`), and three example decks: CCNA OSPF (in JSON and Markdown), PowerShell essentials (code blocks), and TCP/IP fundamentals (diagrams and a table). Tests keep the documents in step with the code.
- A line under a choice that is indented but looks like a field label (for example `Explanation:`) is now an import error with a clear message, instead of silently becoming part of the choice. This is what a Markdown formatter does to a deck.
- "Copy errors for Claude" now asks for the corrected deck in the same format as the one you imported.
- Each release will carry the deck schema, the Claude skill as a zip, and a checksum file as downloads next to the container image, and the image is scanned for known vulnerabilities before a release can go out.
- Optional API token: with `TESSERA_API_TOKEN` set, scripts and tools calling `/api/*` must send `Authorization: Bearer <token>`. The web page keeps working without it, including over plain HTTP on a network address. Another website cannot reach the API through a visitor's browser. The token does not protect the web page itself, which has no login: keep it behind a VPN or a reverse proxy that asks for a password (see the deployment guide).
- Home screen with a deck list and counts.
- Light and dark themes that follow the system, usable on a phone.
- Docker image for `linux/amd64` and `linux/arm64`, a hardened `compose.yaml`, a health check, and graceful shutdown.
- Automatic backup before any database upgrade, and a documented way to take a backup while running.
- Operations guide, deployment guide, security page, and release process in `docs/`.

### Security

- Markdown in cards is rendered safely: raw HTML is shown as text, images and unsafe links are removed, and the result is sanitized again before it reaches the page.
- Content Security Policy, JSON-only write endpoints, no cross-origin access, request size limits, strict input validation, and logs that never contain card text.
- The port is published on `127.0.0.1` only by default. See the deployment guide before opening it up. There is no login.
- Tessera now refuses requests that arrive under a host name it is not meant to answer to, which blocks DNS rebinding attacks from hostile web pages. It answers `localhost`, any IP address, single-word names, and `.local`, `.lan`, `.home.arpa`, `.internal`, and `.localdomain` names by default. **If you reach Tessera by a real domain name, for example through a reverse proxy, set `TESSERA_ALLOWED_HOSTS`.** The refusal message says so.

### Fixed

- A request body over the size limit, sent in chunks, returned a server error instead of "too large".
- The study screen had no page heading for screen readers.
- A system clock that jumps backwards could make a card you had just answered impossible to answer again until the clock caught up.
- Two copies of Tessera on one data folder (for example an old container still running during an upgrade) made imports fail with "database is locked".
- A damaged database file produced an unexplained "file is not a database". It now names the file and says how to recover.
- Rolling back to an older version after an upgrade could silently open a newer database. It now refuses and explains.

### Known limitations

- Leech handling, cram mode, and statistics are not built yet.
- Browser tests run in Chrome, Firefox, and WebKit (the engine of Safari). Tessera has not been tried on a real Safari, iPhone, or Android device, or with a screen reader. Safari does not Tab to links by default, so on Safari use Option+Tab to reach links.
